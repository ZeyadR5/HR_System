# ⏱️ الدليل الشامل لمفهوم الـ Exponential Backoff (التراجع الأسي الذكي)

الـ **Exponential Backoff (التراجع الأسي / التمهل التدريجي المضاعف)** هو استراتيجية ذكية جداً في هندسة البرمجيات للتعامل مع **الأخطاء المؤقتة، ضغط الشبكات، وفشل الاتصال بالسيرفرات والـ APIs**.

---

## 🚪 مثال من الحياة اليومية يفهمك الفكرة في ثانية:

تخيل أنك ذهبت لصديقك وطرقت بابه:

### 1. الطريقة البدائية (بدون Backoff):
- لم يفتح، فبدأت تطرق الباب بسرعة جنونية وبدون توقف: *طرق، طرق، طرق، طرق!*
- **النتيجة:** صديقك قد يكون مشغولاً أو يحل مشكلة طارئة، وطرقك المستمر سيعطله ويزعجه وقد يكسر الباب أو يرفض فتح الباب نهائياً!

### 2. طريقة الـ Exponential Backoff (الذكية):
- تطرق الباب مرة واحدة.. لم يفتح؟
- تنتظر **1 ثانية** ثم تطرق ثانية.
- لم يفتح؟ تضاعف مدة الانتظار وتنتظر **2 ثانية**.
- لم يفتح؟ تضاعف وتنتظر **4 ثوانٍ**.
- لم يفتح؟ تضاعف وتنتظر **8 ثوانٍ**.. ثم **16 ثانية**.. وهكذا.

> 💡 **القاعدة:** أنت تعطي الطرف الآخر **وقتاً أطول تدريجياً ليتعافى ويحل مشكلته** قبل أن تحاول التواصل معه مجدداً.

---

## 📈 المعادلة الرياضية ببساطة:

في كل محاولة فاشلة، نضاعف مدة الانتظار بالأس:

$$\text{Wait Time} = \text{Base} \times 2^{\text{Attempt Number}}$$

- **المحاولة الأولى:** انتظر $1 \times 2^1 = 2$ ثانية.
- **المحاولة الثانية:** انتظر $1 \times 2^2 = 4$ ثوانٍ.
- **المحاولة الثالثة:** انتظر $1 \times 2^3 = 8$ ثوانٍ.
- **المحاولة الرابعة:** انتظر $1 \times 2^4 = 16$ ثانية.
- **المحاولة الخامسة:** انتظر $1 \times 2^5 = 32$ ثانية.

## ⚠️ مشكلة «القطيع المتدافع» (Thundering Herd) والسر المسمى Jitter:

تخيل أن سيرفر إرسال إشعارات الواتساب أو OneSignal تعطل لمدة 10 ثوانٍ، وكان هناك **10,000 مستخدم** يحاولون إرسال رسائل في نفس اللحظة:
- لو كل الـ 10,000 مستخدم انتظروا بالضبط 2 ثانية ثم هجموا معاً على السيرفر.. السيرفر سيسقط مجدداً!
- ثم بعد 4 ثوانٍ سيهجم الـ 10,000 معاً في نفس اللحظة.. ويسقط مجدداً!

### 🎲 الحل السحري: إضافة الـ **Jitter (العشوائية)**
نضيف جزءاً عشوائياً صغيراً من الثواني لكل محاولة:
- جهاز ينتظر: `2.3` ثانية.
- جهاز آخر ينتظر: `1.8` ثانية.
- جهاز ثالث ينتظر: `2.6` ثانية.

> بهذا تتوزع المحاولات بسلاسة وبشكل متباعد دون أن تهجم جميعها في اللحظة نفسها.

## 🛠️ أين يُستخدم الـ Exponential Backoff في Laravel؟

### 1️⃣ في الطوابير ومعالجة الوظائف في الخلفية (Laravel Queues & Jobs):
في لارفيل، إذا كنت ترسل إشعارات موبايل (OneSignal) أو رسائل بريد أو مزامنة بيانات جهاز البصمة، وفشلت العملية بسبب ضعف الإنترنت:
تستطيع كتابة سطر واحد في الـ Job ليقوم بالـ Exponential Backoff تلقائياً:

```php
namespace App\Jobs;

use Illuminate\Contracts\Queue\ShouldQueue;

class SendMobilePushNotification implements ShouldQueue
{
    // أقصى عدد محاولات
    public $tries = 5;

    // فترات الانتظار المضاعفة بالثواني: 2 ثانية، ثم 10، ثم 30، ثم 60 ثانية
    public $backoff = [2, 10, 30, 60];
}
```

أو تركه يحسبها أسياً بدالة ديناميكية:

```php
public function backoff(): array
{
    // [1, 2, 4, 8, 16]
    return [1, 2, 4, 8, 16];
}
```

---

### 2️⃣ عند الاتصال بـ APIs خارجية (مثل OneSignal أو WhatsApp أو بوابات الدفع):
إذا أرسلت طلباً لخدمة خارجية وأرجعت لك كود `429 Too Many Requests` (تجاوزت حد الطلبات في الدقيقة):
- لا تكرر الطلب فوراً حتى لا يتم حظر الآي بي (IP Ban) الخاص بسيرفرك.
- تستخدم `Http Client` المدمج في لارفيل والمزود بالـ Retry الأسي:

```php
use Illuminate\Support\Facades\Http;
use Illuminate\Http\Client\ConnectionException;

$response = Http::retry(3, 100, function ($exception, $request) {
    // إعادة المحاولة 3 مرات مع تضاعف وقت الانتظار تلقائياً (Exponential)
    return $exception instanceof ConnectionException;
}, throw: false)->post('https://api.onesignal.com/notifications', [
    // البيانات
]);
```

---

### 3️⃣ عند حدوث تصادم في قاعدة البيانات (Deadlocks):
إذا حاول مشرفان تعديل نفس السجل في نفس الفيمتو ثانية، لارفيل توفر دالة `DB::transaction` مع عدد محاولات مدمج فيها تراجع زمني ذكي:

```php
use Illuminate\Support\Facades\DB;

DB::transaction(function () {
    // الكود الحساس
}, 5); // 5 محاولات إعادة تلقائية ذكية
```

---

## 🎯 خلاصة القيمة:
- **بدون Exponential Backoff:** السيرفرات تحرق طاقتها وتتسبب في إسقاط بعضها البعض (Self-inflicted DDoS).
- **باستخدام Exponential Backoff:** يتعامل النظام بأناقة وصبر مع أخطاء الشبكات وانقطاعات السيرفرات دون أن يشعر المستخدم بأي انهيار.
